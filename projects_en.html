01CURRENT PROJECT

Booking

In development

An appointment booking system for beauty and wellness businesses

Project repository ↗

A practice web application where fictional businesses can manage appointments. Customers can browse services, book appointments, and cancel them. The application is not intended to be a real product.

TECHNOLOGIES ReactTailwindNode.jsExpress PostgreSQLTypeScriptDockerKysely

01 / STRUCTURE

The foundation

  • The PostgreSQL database runs in a Docker container, and its data is stored in a volume defined in Compose.
  • The frontend, backend, and database run in separate containers.
  • The server uses node-postgres for database connections and Kysely for building TypeScript-compatible queries.

Use of AI

  • Dockerfile and Compose files.

02 / PROGRESS

MVP and future plans

MVP in progress

  1. Choose between different business types, such as hair salons and massage studios
  2. Browse businesses' services
  3. Customer registration and login, with cookie-based sessions
  4. Book appointments
  5. View personal bookings
Plans for the final version
  • Business registration and login, and appointment management
  • Add, edit, and remove services
  • Manage staff skills and business information
  • Allow customers to cancel appointments
“

WHAT MAKES THIS PROJECT INTERESTING

Concurrency and a smooth booking experience

I started the application to practice designing and developing similar services and to learn new tools. The most interesting challenge is preventing double bookings and showing other users' booked times in real time. I am considering using WebSockets, along with provisional bookings and transactions on the backend.

The solutions may change as development progresses. State management currently lives in React components, and I also plan to improve accessibility during development.

02COMPLETED PROJECT

BUILT ITERATIVELY

Quiz App — Trivia app

Project repository ↗

A simple trivia idea grew into a Node.js and React application where users can play, create, and edit their own quizzes. I developed it intermittently for almost a year, and I have also used it to support my own studies by creating quizzes on lecture topics for personal use.

The project is available on Render.

TECHNOLOGIES Node.jsExpressReactTailwindMongoDB AtlasMongooseRedux ToolkitTypeScript

01 / FEATURES

Quizzes for play and study

  • Answer multiple-choice questions about music, television, history, and many other topics.
  • Register to create your own quizzes for entertainment or to help with studying.
  • Edit or remove quizzes you have created.
  • The responsive design works on desktop and mobile devices.

PROJECT GOALS

  1. Build a larger full-stack project of my own for my portfolio.
  2. Strengthen the skills and tools learned in the Full Stack Open course, such as TypeScript.

I chose the technologies mainly for familiarity and practice.

02 / IMPLEMENTATION

Implementation and technologies

  • Type safety and validation: Static typing with TypeScript; Mongoose and Zod validate data at runtime.
  • Authentication and security: User authentication and authorization are token-based.
  • Testing: Unit and component tests, API tests, and Playwright end-to-end tests.
  • CI: GitHub Actions automates frontend component tests and production build verification.
  • Frontend: React for the user interface, React Router for routing, and Redux Toolkit for state management; styling and responsiveness use vanilla CSS and Tailwind CSS.
  • Backend: Node.js and Express for application logic and REST APIs.
  • Cloud database: MongoDB Atlas for flexible schemas and future changes.

Use of AI

  • Redux Toolkit selectors and their compatibility with TypeScript.
  • Form components used to create quizzes.

03 / LEARNINGS

Work and lessons learned

One challenge was working on the project intermittently and iteratively. I worked on it alongside my studies, so I had to get back up to speed after longer breaks. The documentation I wrote about my work helped with this.

When I started the project, I only had a rough idea of the outcome, so the implementation and tools changed as I went. This also gave me valuable practice in refactoring. Another goal was to practice TypeScript, and integrating it with the other tools was sometimes challenging.
